## Findings found but not planned yet (broad refactors; plan on request)

- Shared HTTP client factory and `TransportError` in `kairo-net`: six reqwest clients
  (some with no timeout) and four error classifiers that parse text back into types.
- Shared streaming download helper (updater, scripture pack, slide converter each hash,
  size-check and fsync differently).
- `PowerEvent { Resume, Focus }` topic on `AppCore` instead of per-service wake calls
  and the 5 s wall-clock poll in `kairo-cloud/src/session.rs`.
- Unify ~10 ad-hoc listener registries onto `kairo_core::topic` (`Publisher`/`Watch`);
  `kairo-media/src/publish.rs` also never closes for cloned subscriptions.
- Orchestrator duplicates `kairo_core::resilience::{monitor, probe_after_delay}`.
- Detector polls on a fixed 50 ms ticker; switch to deadline + `Notify`.
- One `Clock`/`now_ms` seam and one `Backoff` type in `kairo-core`; drop test-only
  `Sleep`/`sim_step` fields from production structs.
- Efficiency: `citation.rs` lookaround-wrapped `\b` forces backtracking regex for ~28
  passes per transcript; quote search tokenizes candidates 3 to 4 times per search;
  service records re-serialize the whole archive per transcript segment.
- Crash ledger read-modify-write is not serialized (`kairo-store/src/crash.rs`).
- Transfer previews accumulate in `pending` until commit/discard.

## Findings considered and rejected

- Unify `locale_compare` across crates: moving the feruca collator into `kairo-domain`
  adds a dependency to every crate for one sort; revisit when a third crate needs it.
- Replace `utf16_prefix` in `live_detector.rs` with `slice_utf16`: the lossy variant can
  differ on split surrogates; parity risk outweighs the dedup.
