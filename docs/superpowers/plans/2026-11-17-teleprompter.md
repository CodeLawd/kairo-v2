# Teleprompter Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task by task.

**Goal** — Let an operator paste, type, or import a script from Word or PDF, then control its playback on a presenter’s stage display.

**Architecture** — Kairo owns saved scripts and operator controls. The render engine owns frame-by-frame scrolling. Reuse existing stage display assignment, routing, and reconnect behavior.

**Tech stack** — Rust, GPUI Kit, the native scene renderer, the existing engine protocol, and bundled PDFium.

**Release scope** — A local library of saved scripts, with one loaded script and one teleprompter stage display at a time. Word import supports modern `.docx`. PDF import supports files with extractable text. Legacy `.doc`, OCR, and speech-following are follow-up work. Estimate **10–15 engineering days** for one developer, including import fixtures and packaged display verification.

## 1. Prove playback on the stage renderer

- [ ] Model playback separately from stage content before building the prototype. Hold a script revision, monotonic time anchor, position, speed, and play state in the engine. Re-anchor on pause, resume, seek, or speed change. Clamp to the script bounds and pause at the end.
- [ ] Prototype a clipped viewport and fixed reading guide. Use the stage planner in `apps/kairo-engine/src/program.rs`, the live-piece pattern in `crates/kairo-scene/src/program/mod.rs`, and layer drawing in `apps/kairo-engine/src/layers.rs` as integration points. Cache shaped lines and draw only the visible range. Keep the existing horizontal ticker motion independent. If profiling favors pre-rasterized text, use bounded tiles so long scripts fit the GPU texture limit.
- [ ] Lay out the teleprompter using the target display's drawable dimensions. Keep the recovery position as a UTF-8 byte offset at a valid character boundary for the current revision. Resolve it to the line at the guide after reflow. Use lines per second for operator speed and derive pixel travel from line layout.
- [ ] Verify on a real second monitor at slow and fast speeds with a 10,000-word script. Measure frame pacing and check that transport changes leave shaped text cached, pausing holds the current line, font changes preserve the reading anchor, and portrait layout fills the available viewport. Verify GPUI Kit's multiline input remains responsive when pasting, editing, and scrolling the same script. Use the results to confirm the renderer and editor approach and revise the estimate before full implementation.

## 2. Persist editable scripts and import Word and PDF

- [ ] Add a script record in `crates/kairo-domain/src/teleprompter.rs` with stable ID, title, plain-text body, and update timestamp. Add local listing and loading plus atomic saves through `crates/kairo-store`. Keep edits recoverable across restart and leave playback paused on launch.
- [ ] Add a service in `crates/kairo-documents/src/script_import.rs` that takes a selected file and returns editable text plus any extraction warnings. Perform file IO and extraction on a worker. Limit input bytes, decompressed DOCX content, and extracted text. Surface file errors in the editor and preserve the current draft if an import fails or is cancelled.
- [ ] For DOCX, reuse the existing `zip` and `roxmltree` dependencies to extract the document body in order. Preserve paragraph breaks, line breaks, and readable separation between table cells. Handle tabs, explicit line breaks, and soft hyphens. Read one supported markup compatibility branch so text boxes do not appear twice. Skip field instructions, headers, footers, footnotes, comments, and deleted revisions. Keep processing local and ignore external relationships and embedded objects.
- [ ] For PDF, reuse the loader in `crates/kairo-documents/src/pdf.rs` and extract text page by page. Clean up line endings and preserve page boundaries as paragraph breaks. Tell operators to review the preview for reading order, especially with columns. If some pages have zero extractable text, identify those pages. If the entire PDF has no text, explain that it may be scanned and needs a text-enabled copy. Reuse the loader’s password error for locked PDFs.
- [ ] Add fixtures for DOCX paragraphs and tables, alternate text-box markup, field instructions, whitespace and Unicode, text PDFs, mixed scanned and text pages, wholly scanned and locked PDFs, corrupt input, and oversized archives. Verify editing and reopening an imported script with the original file removed. Run `cargo test -p kairo-documents -p kairo-store` with PDFium available.

## 3. Route the teleprompter to its assigned display

- [ ] Add `StageDisplayMode` to `StageDisplayConfig` in `crates/kairo-domain/src/program.rs`. Use a serde default of Confidence Monitor and preserve that default during normalization of older settings. Add the mode selector in `crates/ui-screens/src/window.rs`. Reuse display identification and the existing priority given to audience screens.
- [ ] Define a tagged Confidence Monitor or Teleprompter stage payload. The teleprompter payload carries script revision, text, and layout settings. Update the stage payload producers in `crates/kairo-output/src/manager.rs`, decode check in `apps/kairo-engine/src/app.rs`, and stage planning in `apps/kairo-engine/src/program.rs`. Send content on load and content or layout changes. For a live edit to the loaded script, map the current text anchor through the edit into the new revision. Preserve anchors in unchanged text, shift them for edits before the anchor, and snap to the nearest surviving character boundary when the edit overlaps the anchor. Use the start only if no valid anchor can be recovered. An unrelated script starts at the top. Opening a fresh engine surface initializes it paused.
- [ ] Add a separate `StageTransport` command in `crates/kairo-engine-proto/src/messages.rs`, keyed by surface, script revision, and a per-session command sequence. Carry play, pause, seek, and speed as typed operations. Apply them in the engine by updating the playback anchor and scheduling a frame. Keep transport out of the stage rebuild and display reconciliation paths. Ignore stale revisions, stale sequences within the current session, and commands targeting confidence monitors. When a new engine session begins, reset the output manager’s outgoing transport sequence and incoming acknowledgement tracking. Reject late events from the retired session using connection identity or a session generation.
- [ ] Add a `StagePosition` event with surface, revision, last applied transport sequence, current text anchor, and play state. Emit after applying transport, at end of script, and once per second during playback. Keep the latest valid checkpoint in the output manager independently of the session’s sequence tracking. When publishing a live edit, associate the mapped anchor with the new revision so reconnect can recover it before the first new position event arrives. On disconnect or engine restart, replay stage content via `crates/kairo-engine-proto/src/surface.rs` and initialize playback at that checkpoint paused. Replay carries no historical play commands. Fall back to the start if the checkpoint is missing or belongs to another revision.
- [ ] Test deserialization of old settings, mode switches, display conflicts, playback at end of script, stale commands and checkpoints, reconnect, and script replacement during playback. Test a live typo correction before and across the reading anchor, including multibyte text. Verify that playback keeps its place through the revision change and an immediate reconnect. Restart the engine after a high sequence has been acknowledged, accept the first low-sequence command and position event from the new session, and reject a delayed event from the retired session. Assert that transport does not create a new stage layer or reconcile display windows, and replay cannot resume playback. Check that an audience push or clear leaves the teleprompter running and that other confidence monitors retain their layout. Run the output, protocol, and engine tests.

## 4. Build the operator workflow and verify packaged builds

- [ ] Add the Teleprompter view under `crates/ui-operator/src/teleprompter/` with playback controls in `playback_controls.rs` and wire app-level registration and commands through `apps/kairo/src/operator.rs` and `apps/kairo/src/actions.rs`. Provide a saved-script picker, a multiline editor, an **Import Word or PDF** picker, an editable extraction preview, and a separate **Load on display** action. Open the preview before replacing the current draft or publishing text to a live display.
- [ ] Provide play/pause, restart, manual scrolling, speed and text size, and keyboard shortcuts scoped away from the script editor. Show the selected display, whether it is connected, and whether playback is paused or running. Use the current text anchor to preserve the line at the reading guide when a font-size change rewraps the text.
- [ ] Verify the complete flow on the desktop platforms Kairo ships. Import each format with the packaged app, correct text in the preview, save and reopen the script, assign a second display, run playback, change speed, pause, seek, and reconnect. Exercise active audience output throughout. Run package-level tests for every touched crate.
- [ ] If the first deployment uses a beam-splitter rig, include horizontal mirroring and verify it on that hardware. Mirror the presenter text while preserving normal operator controls and preview.

## Acceptance

An operator can import a DOCX or a text-based PDF, correct the extracted text, and deploy it to the selected stage monitor. Playback remains smooth during a long reading, pauses at the end, and retains its place through pause and resume. A failed import leaves the draft intact, a disconnected display returns paused, and audience projection continues independently.
