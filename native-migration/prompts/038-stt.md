## 4. Implementation requirements

1. Capture with `cpal` on its realtime thread and push into an SPSC ring. Resample to 16 kHz mono PCM16 with `rubato`, off the callback. Emit levels at the existing rate.
2. Device selection: reproduce stored `audio.deviceId` semantics, and map old Chromium device IDs on first run by label. Handle hot-unplug and default-device change.
3. Request macOS microphone permission with the same purpose string. Handle denial states as the UI expects.
4. Port Deepgram over `tokio-tungstenite`. Connect with a short-lived grant from `licensing.transcription()`, with renewal (retry 5, 15, 30 s) and release. Handle "another computer is using transcription" (wait 30 s, up to 8 tries) and treat other 4xx as a final refusal with the server's reason. Query: `nova-3`, language, punctuate, smart_format, no_delay, repeated `keyterm=`, interim_results, utterance_end_ms 1500, vad_events, linear16, 16000 Hz, 1 channel. Reconnect backoff 1 to 30 s, 20 tries. Keep 30 s replay, keepalive, connection generation and audio epoch logic, and confirm the URL against what `@deepgram/sdk` produces.
5. Keep the `KAIRO_STT_REPLAY_PATH` development replay and `licensing.assertFeature('transcription')`.

Edge cases: list every error, empty and failure path you find in the source above, and handle each one. Add any that the source handles and this prompt does not name.
